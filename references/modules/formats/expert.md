# 专家访谈

## 适用对象

掌握组织、行业、专业流程、战略决策或技术判断的知情者。专家身份由当前主题的经验和知识决定，不等于职位名称。简报记录专家和研究对象的关系：在职、前雇员、合作方还是独立专家，以及层级和离开时间。这决定了他能看到什么，也决定证据的分量。

## 用途

专家访谈先定用途。用途决定问什么、问哪个时间段、追问追什么。一场访谈定一个主用途，最多再带一个辅助用途，写进简报的“用途”一行。

| 用途 | 要回答的问题 | 时间重心 | 追问追什么 | 产出 |
|---|---|---|---|---|
| 学做法 | 对方是怎么做成的 | 过去的项目和决策 | 案例、过程、谁来决定、指标、失败和反例 | 可借鉴的做法和适用条件 |
| 拼规划 | 对方接下来要做什么 | 现在的投入和下一步 | 迹象、来源、把握、时间点、依赖 | 一张规划拼图，每块标来源和把握 |
| 看格局 | 这个领域怎么运转、往哪走 | 现在到未来一两年 | 参与者、分工、驱动因素、拐点、反例 | 格局和趋势判断，每条标依据 |
| 评技术 | 某项技术或方案做不做得成、卡在哪 | 现状和到达目标的路径 | 指标、瓶颈、成本、替代路线、时间 | 成熟度判断和关键瓶颈 |
| 验假设 | 我方的判断或方案站不站得住 | 我方的假设 | 反例、成立条件、风险 | 每条假设：支持、反对或有条件成立 |
| 内部对齐 | 内部各方怎么看、需要什么 | 现状和期望 | 角色、诉求、约束、分歧 | 需求和分歧清单 |

用途能从请求里看出来就直接用：“想知道对方下一步做什么”是拼规划，“想学对方怎么做成”是学做法。看不出来时，首轮问一次。

## 各用途的节奏和问法

**学做法：** 角色边界 → 一个真实项目从头讲 → 决策和取舍 → 指标 → 失败和反例。用方法卡 15–19。

**拼规划：** 方向排序 → 资源投入 → 能力缺口 → 路径和时间点 → 约束和风险 → 对外卖点。过去的项目只用来支撑判断，不展开复盘。

- 主问示例：“在您看来，[对象]接下来一两年最优先投入的是哪几块？”
- 每个判断都追：“从哪些迹象看出来的？”“您有多大把握？”“大概什么时候能看到？”“它要先解决什么才做得成？”
- 区分亲眼所见、听说和自己推测，简报的证据边界按这三类标注。

**看格局：** 参与者和分工 → 谁靠什么赚钱 → 驱动因素 → 拐点和不确定性 → 反例。

- 主问示例：“这个领域现在主要是哪几类玩家，各自靠什么立住？”
- 追问：“这个判断依据是什么？”“有没有反过来的例子？”“什么变化会让格局改写？”

**评技术：** 现状水平 → 和目标的差距 → 主要瓶颈 → 突破路径和时间 → 替代路线。

- 主问示例：“[技术]现在做到什么程度了？离[目标]还差在哪？”
- 追问：“用什么指标判断？”“卡在算法、数据、算力、成本还是工程？”“突破大概要多久？”“有没有别的路线？”

**验假设：** 先让专家讲自己的判断，再亮出我方假设。每条假设追反例和成立条件。

- 先问：“您怎么看[议题]？”讲完再问：“有一种看法是[假设]，您觉得在什么情况下成立，什么情况下不成立？”
- 亮假设之前，不暗示我方立场。

**内部对齐：** 角色和职责 → 现状 → 期望和顾虑 → 约束 → 分歧。用方法卡 15–17。

- 主问示例：“这件事在您这边，最希望它解决什么？”

## 概念问题

专家可以概念先行。研究员和专家共享术语时，可以直接问概念问题，获取专家的框架和判断，例如“您会如何拆解这个问题？”。概念问题不能是唯一证据，每个重要判断按上面的用途补追问，不停留在口号和抽象结论。不要为了口语化，把专家的概念问题改成普通用户式的生活化假设。

## 问法规则

- 研究员命名的内部分类，不写成专家必须接受的前提。
- 不问对方现任或前任雇主的非公开机密：未发布产品的具体规格和日期、内部财务和合同数字、代码和内部文件。拼规划和评技术不靠这些，靠方向、排序、区间、资源流向、依赖和可观察的迹象拼出来。
- 对方不便细说时，按用途换问法，不换掉目标：学做法改问通用做法；拼规划和评技术改问方向、排序、区间和依赖。
- 成功案例后补失败案例、反例或不成立的条件。

## 约访方式

- **双盲专家网络：** 不介绍发起方。开场只说主题和时长，不逐项声明用途、记录、匿名、跳过和退出；这些按专家网络的条款执行，写进简报。
- **直接约访的外部专家：** 按任务路由的常规同意流程。
- **内部专家：** 说明内容用途、是否署名，以及是否会反馈给管理者。
