# 专家访谈

## 适用对象

掌握组织、行业、专业流程、战略决策或技术判断的知情者。专家身份由当前主题的经验和知识决定，不等于职位名称。

## 核心证据

- 专家的概念模型和判断框架。
- 真实案例、决策过程、资源取舍和组织约束。
- 判断依据、指标、边界、反例和可能变化。
- 本人经验、团队经验、行业观察和预测之间的区别。

## 推荐节奏

```text
开场与身份边界 → 主题框架 → 关键案例 → 决策和过程 → 约束、取舍与反例 → 趋势或未来判断 → 总结收尾
```

## 概念问题

专家可以概念先行。研究员和专家共享术语时，可以直接问概念问题，用来获取专家的概念模型和判断框架：

- 战略判断：“这个业务最关键的控制点是什么？”
- 专业框架：“您会如何拆解这个问题？”
- 组织判断：“这个变化对团队分工带来了什么影响？”
- 趋势判断：“未来一到三年最可能发生什么变化？”

概念问题不能是唯一证据。每个重要判断至少补一类追问，不能停留在口号和抽象结论：

- **案例：** “能讲一个真实项目吗？”
- **过程：** “当时具体怎么推进？”
- **依据：** “您根据什么做这个判断？”
- **边界：** “什么情况下这个判断不成立？”
- **取舍：** “如果资源减少，优先保留什么？”

示例：

```text
主问：[产品或业务]的战略控制点放在哪些方面？
追问：您为什么把这些看成控制点？
追问：哪个真实项目或决策体现了这一点？
追问：这个判断受哪些资源、指标或约束影响？
```

不要为了追求口语化，把专家的概念问题强行改成普通用户式的生活化假设。概念问题获得框架和判断，案例问题获得事实和证据，二者组合才能判断专家观点是否有实际支撑。

## 问法规则

- 研究员命名的内部分类不写成专家必须接受的前提。
- 外部专家不方便披露时，允许回答范围、变化、公开案例或匿名经验。

## 场景专属规则

- 战略研究：用大话题牵引讨论，再落到控制点、决策、资源和指标。
- 组织研究：追角色边界、协作关系、流程重建和决策机制。
- 技术或专业研究：追标准、约束、失败模式、替代和适用边界。
- 内部专家：说明内容用途、是否署名以及是否会反馈给管理者。
- 外部专家：包括在职专家、前雇员和独立专家。开场确认身份、立场、匿名和可公开范围。外部在职专家要在首轮确认的事项见任务路由。
- 涉及 NDA 时，改问通用方法、判断逻辑、公开案例或匿名化经验。
- 成功案例后补失败案例、反例或不成立的条件。
