# 访谈方法索引

先根据研究要获得的证据选择 1 个主方法。只有能增加证据且不挤占关键时间时才加入辅助方法。读取本索引后，只读取对应分类文件中的方法卡；不要整篇读取方法库。

## 一、按证据选择

| 需要获得的证据 | 优先读取的方法卡 |
| --- | --- |
| 真实行为、事件顺序和转折 | 关键事件技术、时间线和历史回顾、最近一次和典型案例法 |
| 日常使用、场景和设备角色 | 典型的一天和用户旅程、场景—任务—设备—操作拆解、设备角色和生态关系映射 |
| 触发、任务、成功标准和替代 | JTBD 任务分析、未满足需求和替代方案 |
| 为什么不用、低频使用或放弃 | 非使用、低频使用和放弃路径、情境访谈和手机桌面巡游 |
| 体验差异、评价和改进 | 评价标准和属性拆解、体验对比和期望差距、优先级和取舍 |
| 概念理解、卖点和方案选择 | 概念、卖点和刺激物测试、优先级和取舍 |
| 品牌、身份、关系和社会意义 | 品牌联想、投射和情感曲线、社会意义与身份探索 |
| 连续行为和容易遗忘的细节 | 日志、访前作业和现场复盘、关键事件技术 |
| 专家角色、组织和流程 | 专家角色与边界确认、组织架构和协作关系映射、工作流程和决策机制重建 |
| 专家案例、指标和战略判断 | 专家案例法：成功、失败和反例、指标质量和能力边界、战略判断和反事实追问 |
| 群体语言、共识和分歧 | 群体规则和表达氛围、自由联想和投射、群体比较和差异讨论 |
| 群体中的案例、排序和共创 | 成功故事失败故事和一线案例、座谈会中的刺激物排序和共创 |

## 三、读取规则

- 先读方法卡的“适用问题、核心产出、主问、追问和常见误区”。
- 方法卡中的主问和追问是证据路径示例，追问是候选项。条数按 [工作流](../../products/interview-zh-default/workflow.md) 的内容预算。
- 方法卡中的示例必须按受访者知识边界和项目对象改写，不复制项目名称、样本、指标或历史问法。改写后按 [问法设计](../knowledge/question-craft.md) 的“顺序与偏差”和 [访谈问题表达风格](../../products/interview-zh-default/writing.md) 的“去 AI 腔”逐句检查。
- 方法卡没有覆盖时，使用 [研究设计服务](../../services/research-design.md) 中的“本次适配方案”，不要虚构方法名称或出处。
- 方法选择必须说明所需证据，以及放弃其他方法的原因。说明只进入简报的“方法”一行，不进入现场问题。

## 四、常用组合

| 场景 | 研究任务 | 建议顺序 |
| --- | --- | --- |
| 用户深访 | 购买决策 | 时间线 → 关键事件 → 决策路径 → 评价标准 → 取舍 → 使用后差距 |
| 用户深访 | 使用体验 | 典型的一天 → 场景任务 → 操作复现 → 体验对比 → 未满足任务 |
| 用户深访 | 新功能需求 | 典型场景 → JTBD → 当前替代 → 未满足任务 → 刺激物测试 → 取舍 |
| 专家访谈 | 组织研究 | 角色边界 → 组织映射 → 协作关系 → 流程重建 → 决策机制 |
| 专家访谈 | 战略研究 | 关键事件 → 战略决策 → 资源取舍 → 竞争壁垒 → 指标 → 未来判断 |
| 座谈会 | 概念评价 | 个人初看 → 理解检查 → 场景讨论 → 顾虑 → 群体比较 → 排序 |
| 座谈会 | 需求共创 | 个人场景 → 问题卡片 → 小组聚合 → 方案生成 → 优先级和匿名补充 |
