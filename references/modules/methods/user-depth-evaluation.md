# 用户深访：评价与选择

追问是候选项，用法见 [方法索引](index.md) 的读取规则。

### 8. 评价标准和属性拆解

**适用问题**

- 理解用户如何判断“好”。
- 把产品属性拆成用户能感知的标准。
- 找到宣传、经验和比较基准对评价的影响。

**核心产出**

- 用户的评价维度。
- 评价标准和判断阈值。
- 比较对象和参考基准。
- 标准的形成来源。

**主问**

> 讲讲最近一次用它的情况。

必要时追问：当时心里是拿什么跟它比的？

**追问**

- 您说的“好”，是指哪一点？
- 什么时候这一点最要紧？
- 差到什么程度，您就不想用了？
- 这个标准是自己用出来的，还是听别人说的？
- 哪些地方过得去就行，哪些地方一定要好？

**属性拆解链路**

> 产品属性 → 功能结果 → 使用结果 → 情绪价值或社会价值。


**常见误区**

- 只收集属性名称，不追问属性带来的结果。
- 把研究员定义的指标直接当成用户标准。
- 不追问用户的比较对象和可接受阈值。

### 9. 体验对比和期望差距

**适用问题**

- 本品与旧产品对比。
- 本品与竞品对比。
- 购买前预期与使用后感受对比。
- 试用后品牌态度或购买意愿变化。

**核心产出**

- 体验优势和劣势。
- 有实际影响的差异。
- 预期落差。
- 导致转化或流失的差异点。

**主问**

> 跟您原来用的比，用起来有什么不一样？

**追问**

- 哪里比原来好？
- 哪里不如原来？
- 这些不一样，有没有耽误您办事？
- 买之前想到会这样吗？
- 用了一段时间以后，这一点还重要吗？
- 有没有因为这点，想过换回去？

**常见误区**

- 只问总体喜欢哪一个。
- 只比较产品功能，不比较任务结果。
- 把体验后的即时新鲜感当成长久价值。


### 10. 优先级、排序和取舍

**适用问题**

- 识别最重要的因素。
- 判断一票否决项和可妥协项。
- 研究功能优先级。
- 研究价格、性能和体验之间的取舍。

**核心产出**

- 核心因素和次要因素。
- 一票否决项和可妥协项。
- 不同场景下的优先级变化。
- 取舍发生的条件和原因。

**常用工具**

- 选择最重要的三个。
- 排序。
- 二选一。
- 必须有、最好有、可以没有。
- 预算分配。
- 价格变化后的重新选择。

**主问**

> 刚才说到的这些，只能留三样的话，您留哪三样？

**追问**

- 哪一个最重要？
- 哪一样没有，您就不会选它？
- 哪一样差一点也能接受？
- [提到过预算变化]：预算变了以后，当时是怎么重新挑的？
- 如果只能改进一个地方，您会选哪里？
- 换个场合，比如出门在外，哪样会往前排？

**常见误区**

- 在用户还没有自由表达前就让其排序。
- 把口头排序或“只能改一处”的回答直接当成真实购买权重或需求优先级。
- 不追问排序背后的场景和取舍理由。


### 11. 概念、卖点和刺激物测试

**适用问题**

- 用户是否理解一个概念。
- 用户是否认为概念与自己有关。
- 用户是否相信概念能够实现。
- 用户在哪些真实场景里可能用得上。
- 用户有哪些顾虑。

**核心产出**

- 用户对概念的自然理解。
- 用户认为概念是否与自己相关。
- 吸引点、疑问、顾虑和使用条件。
- 概念与现有方案的差异价值。

**推荐顺序**

> 自然认知 → 展示刺激物 → 理解检查 → 相关性 → 吸引力 → 顾虑 → 使用场景 → 价值判断。

**主问**

> 我先不解释。您看到这个，第一反应是什么？

**追问**

- 您觉得它是做什么用的？
- 哪里让您有点兴趣，哪里没什么感觉？
- 哪里看不明白，或者不太信？
- 最近有没有碰到过用得上它的事？
- 对照您自己的情况，它跟哪件事有关？
- 有什么不放心的地方？
- 跟您现在的办法比，差别在哪？

**常见误区**

- 先替用户解释概念。
- 把“听起来不错”当成真实需求。
- 只问喜欢程度，不问使用条件和顾虑。
- 先报功能名或品牌，再问第一反应。
- 把“会用”“想买”当成需求证据。意愿类回答只记录为态度。
