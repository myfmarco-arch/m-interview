# 用户深访：场景与任务

追问是候选项，用法见 [方法索引](index.md) 的读取规则。

### 4. 典型的一天和用户旅程

**适用问题**

- 了解产品在日常生活中的位置。
- 识别高频使用时刻和关键场景。
- 了解工作日、周末和特殊日期的差异。

**核心产出**

- 按时间排列的使用场景。
- 每个场景中的任务、设备和操作。
- 高频场景、低频高价值场景和体验断点。

**主问**

> 请带我走一遍您工作日的一天，从早上开始讲，产品在什么时刻出现。

**追问**

- 这件事通常发生在什么时间和地点？
- 当时想完成什么？
- 使用了哪个设备或功能？
- 这是特意选的这台设备，还是习惯用它？
- 中间有没有换到别的设备或 App 上？
- 哪一步最费劲？
- 周末或出门在外的时候，也这样吗？

**常见误区**

- 只列举功能，不还原一天中的真实顺序。
- 只问“经常使用什么”，不问最近一次。
- 把用户想象中的理想流程当成当前行为。


### 5. 场景—任务—设备—操作拆解

**适用问题**

- 功能需求挖掘。
- 交互路径研究。
- 多设备角色和切换研究。
- 具体痛点和改进机会研究。

**核心产出**

- 场景条件。
- 用户任务。
- 设备和功能选择。
- 实际操作路径。
- 结果、体验和问题。
- 相关他人、共用关系和社会场合。

**主问**

> 请回忆最近一次使用这个功能的情况，带我从开始到结束走一遍。

**追问**

- 开始使用前发生了什么？
- 一开始先点的哪里？
- 中间有没有哪一步要等，或者要来回切？
- 任务完成后还做了什么？
- 当时有人帮忙、一起决定或和您共用吗？
- 有没有试过其他的操作方式？

**追问顺序**

1. **场景**：什么时候、在哪里、和谁、处于什么状态。
2. **任务**：想完成什么，预期结果是什么。
3. **选择或习惯**：这是特意选择的，还是一直以来就这么用；如果是选择，再问当时为什么。
4. **操作**：具体怎么开始、怎么进行、怎么结束。
5. **结果**：任务是否完成，结果是否可用。
6. **体验**：哪里顺、哪里慢、哪里不确定。
7. **痛点**：哪一步出错、绕路或需要替代方案。
8. **期待**：理想情况下希望怎么完成。放在最后；回答只当态度，不当需求证据。

**常见误区**

- 只问功能是否有用，不问功能解决了什么任务。
- 只问满意度，不问具体操作。
- 把产品功能列表当成用户场景列表。


### 6. JTBD 任务分析

**适用问题**

- 用户为什么在某个时刻选择某种产品或设备。
- 用户希望推动什么事情向前发展。
- 用户当前使用什么替代方案。
- 产品应该创造什么功能、情绪或社会价值。

**核心产出**

- 触发情境。
- 用户想完成的任务。
- 当前替代方案。
- 使用阻力和转换阻力。
- 期望结果和成功标准。

**主问**

> 当时您想把什么事情做成？

必要时追问：为什么这件事在那个时间点变得重要？

**追问**

- 之前通常怎么解决？
- 哪些地方最费力或最不确定？
- （如果受访者提到自己比较过方案）当时为什么选择这个方案？
- 您希望事情变成什么样？
- 做到什么程度，您会觉得这件事完成了？
- 在用它之前，这件事您是怎么解决的？
- 这件事没做好的话，会有什么影响？

**常见误区**

- 直接问“您的 JTBD 是什么”。
- 把功能名称当成任务。
- 把用户的理想愿望直接当成真实任务。


#### JTBD 转换时间线和四种力

购买、换机、迁移或回流研究需要补齐转换过程，不只问最终选择：

```text
第一次产生念头 → 被动留意 → 主动寻找 → 比较和决定 → 开始使用 → 继续、回流或放弃
```

每个阶段检查四种力：

- 推力：对现状的不满或压力。
- 拉力：新方案的吸引或期待。
- 焦虑：对迁移、学习、风险或损失的担心。
- 习惯：旧方案、数据、关系和既有流程带来的依赖。

主问：

> 从第一次产生变化念头开始，请按时间顺序讲讲您后来怎么做决定的。

追问：

- 当时是哪件事，让您不想再用原来的办法了？
- 当时还看了哪些别的办法？
- 当时最担心什么？
- 有什么让您舍不得换，或者犹豫了一下？
- 最后是在什么情况下做的决定？

不要把四种力当成固定选项逐项询问。先让受访者自然讲，再用未提及的力量补问。

### 7. 未满足需求和替代方案

**适用问题**

- 发现产品没有解决的真实问题。
- 解释用户为什么不用某个功能。
- 判断需求是否有频率、强度和替代行为支撑。

**核心产出**

- 未满足任务。
- 发生频率和严重程度。
- 当前替代方案。
- 用户接受的最低结果。
- 潜在机会方向。

**主问**

> 最近一次您觉得产品帮不上忙是什么时候？

必要时追问：当时您想完成什么？

**追问**

- 这个问题多久发生一次？
- 当时最后怎么解决？
- 您有没有放弃、延迟或改用其他方式？
- 换成这种方式，多花了多少时间或钱？
- 这些事里，哪件最让您头疼？

**常见误区**

- 直接问“您还想要什么功能”。
- 只记录用户提出的功能，不记录使用条件。
- 不区分偶发不便和高频刚需。
