# 访谈产出物命名与版本

## 一、默认格式

```text
YYYY-MM-DD_项目简称_文档类型_vNN.md
```

示例：

```text
2026-11-13_大折叠手机购买决策_访谈简报_v01.md
2026-11-13_大折叠手机购买决策_访谈大纲_v01.md
2026-11-13_大折叠手机购买决策_访前案头调研_v01.md
```

字段规则：

- `YYYY-MM-DD`：本次文件发布或修改日期。它不是访谈执行日期；访谈日期写在文档正文。
- `项目简称`：使用稳定、可识别的短名称。不要把完整需求句或版本信息写进项目名。
- `文档类型`：固定使用“访谈简报”“访谈大纲”或“访前案头调研”。
- `vNN`：从 `v01` 开始，使用两位数字递增。不要使用“最终版”“final”“最新版”或“v1-改好”。
- 文件名不使用路径分隔符、系统保留字符、首尾空格或重复版本后缀。

## 二、版本规则

- 首次正式交付使用 `v01`。
- 只要内容再次对外交付，就递增版本号。研究目标、方法、问题、时间预算、执行边界、案头调研结论或排版结构发生变化时，必须递增。
- 同一批交付的简报、大纲和案头调研使用同一个版本号和版本日期。只改其中一份时，下一次交付也同步提升整套文件的版本号；未变动文件可以只同步版本信息。
- 版本号只表示修订顺序，不表示质量状态。不要用 `draft`、`review`、`final` 替代版本号。
- 文件正文至少保留“版本”和“版本日期”。如经过试访或跨场次调整，再记录修改原因和生效场次。

## 三、修改时的处理

1. 读取现有文件名和正文中的版本信息。
2. 保留项目简称和文档类型，只更新日期和版本号。
3. 不覆盖旧版本；生成新文件并保留旧文件供回溯。
4. 检查同一批交付物的版本号、版本日期和相互引用是否一致。

如果用户明确指定了文件名或版本方案，遵循用户指定方案，并在正文中保留可追溯的版本信息。
