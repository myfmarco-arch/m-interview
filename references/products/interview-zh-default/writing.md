# 访谈问题表达风格

目标是让大纲读起来像团队研究员写的，问题像主持人在现场说的话。正式文档只保留有信息价值的句子。

先看“零、团队写法”。它来自团队历史大纲的归纳，和本文其他规则冲突时以它为准。逐题自检见 SKILL.md 第 5 步。

## 零、团队写法

### 1. 格式

| 元素 | 写法 | 例子 |
| --- | --- | --- |
| 模块 | `## 中文序号、模块名（时长）`，模块名用业务名词 | `## 二、换机过程（15mins）` |
| 过渡 | 模块开头一行斜体 | `*接下来，我们聊聊您最近一次换机的过程*` |
| 开场 | 两个小标题：`#### **解释访谈目的和流程**`、`#### **受访者自我介绍**`，下面列要说的话 | 见大纲模板 |
| 主问题 | `#### 【短标签】完整问句`。标签 2–4 个字，说明这题要拿到什么 | `#### 【备选方案】您当时还对比了哪些品牌和机型？` |
| 追问 | 主问题下面逐行列短问句；要拆细时再缩进一层 | `- 当时是出于什么原因更换的？` |
| 分支 | `[分群或条件]：问句` | `- [之前用过安卓]：当时为什么换到 iPhone？` |
| 提示清单 | 斜体一行“没有主动提到的，依次询问：”，下面用引用块列类别 | `> 外观｜影像｜续航｜系统` |
| 主持人提示 | 只在必须据此转向时写一行斜体 | `*从当前这台往前倒推，最多三代*` |
| 收尾 | `## 六、总结（3mins）`，下面列补充、提问、致谢和停止记录 | 见大纲模板 |

### 2. 措辞

- 称呼用“您”。常用开头：“请您帮我回忆一下……”“请您介绍一下……”“当时……”“您是如何……”“为什么……”“有没有……”。
- “如何”“是否”“体验如何”“哪些方面”“因素”“维度”是团队常用词，可以用。用户深访里，“体验如何”“出于什么原因”放在受访者讲完一次具体经历之后，不作为开场主问题。
- 问句写完整，时间、对象说清楚：写“您当时是出于什么原因更换的？”，不写“为啥换？”。
- 不为了显得口语而硬加词。不用“弄”“啥”“咋”“拍板”：“弄过来”写成“迁移过来”或“导过来”，“怎么弄的”写成“怎么操作的”，“拍板”写成“最后决定”。
- 模块名用业务名词，如“换机过程”“使用体验”“概念测试”。不用“回头看”“看一张图”这类口号式名字。
- 主问题只问一件事。唯一允许的连问是“时间或事件锚点 + 开放叙述”，两句说的是同一件事，如“最近一次是什么时候？当时是什么情况？”。回忆和评价、两个不同对象、互不相关的问题，拆成主问和追问。
- 追问同一行最多连问两个紧密相关的小问题，如“是什么时候开始的？当时在哪里？”。
- 评价类问题好坏都问：“哪些地方满意？哪些地方不及预期？”。
- 举例放在括号里或用“比如”带出，例子最多两三个：“您日常主要用手机做什么？（比如工作、拍照、看视频）”。

## 一、共同特征

### 1. 从动作和经历开始

优先使用：

- “帮我回忆一下……”
- “请讲讲……”
- “带我走一遍……”
- “当时怎么做的？”
- “后来呢？”
- “能不能举个例子？”
- “这几块是什么关系？”

少用：

- “请阐述……”
- “请围绕……进行深入分析……”
- “请描述您的核心需求……”
- “您能否提供相关洞察……”

### 2. 具体词优先于抽象词

把“需求、价值、痛点、心智、底层逻辑、核心诉求、抓手、闭环”等研究或管理术语，改成受访者能直接回答的对象、动作、场景和结果。

```text
不问：您对这个功能的核心需求是什么？
改问：您最近一次想完成这件事是什么时候？当时怎么处理的？

不问：这个产品的底层价值是什么？
改问：它具体帮您完成了什么？哪一次最有用？

不问：用户为什么不接受这个方案？
改问：您第一次看到它时怎么理解？后来有没有试过？在哪一步停下来的？
```

专家已经使用某个术语，或研究员与专家共享该语境时，可以保留术语。保留术语后要追问具体案例、过程或边界。

### 3. “为什么”要跟在事件后面

用户深访中，不单独问“为什么买”“为什么喜欢”“为什么不用”。先还原事件，再问当时的判断：

```text
先问：当时看过哪些产品？最后怎么定下来的？
再问：当时为什么更倾向这个？
```

“为什么”不是禁词。它适合连接一个已经讲清楚的动作、选择或变化。

### 4. 不要求受访者替研究员整理

不要要求受访者严格按时间顺序、完整分类或一次讲出全部结论。可以说：

> 从最早想换手机的时候说起就行，想到哪里说到哪里，我来帮您梳理。

主持人负责整理时间线和分类，受访者负责提供经历和判断。

## 二、三类场景的句式

### 用户深访

主问题通常从最近一次、典型场景或现场操作进入：

- “请回忆一下最近一次……从头到尾讲讲。”
- “当时先发生了什么？”
- “带我看看您平时是怎么做的。”
- “哪一步最费劲？”
- “如果没有这个，您通常怎么处理？”

不要把 JTBD、痛点、用户价值、需求层级直接问给用户。

### 专家访谈

概念问题可以直接问，但要像请教，不要像质询，也不要停在概念：

- “在您的经验里，这件事最关键的点是什么？”
- “内部通常怎么判断？”
- “这几块是什么关系？”
- “能不能讲一个实际例子？”
- “哪一步最容易出问题？”
- “什么情况下这个判断不成立？”

对方不便细说时，按用途换问法，不换掉目标（见专家形式模块）：

- 学做法：“行业里通常怎么做？”
- 拼规划：“那换个问法，接下来的投入重心更偏哪一边？”

### 座谈会

先让个人表达，再组织比较：

- “请结合自己的经历说，不用代表所有人。”
- “大家先各自想一下，等会儿我们轮流说。”
- “刚才出现了两种情况，能不能分别讲讲当时发生了什么？”
- “您听到别人这么说，有没有想到自己的经历？”
- “我先听听其他几位，等下再回来听您补充。”

不要让参与者替研究员解释群体差异。先收集各自的经历，差异由研究员分析。

## 三、压缩和去 AI 腔

现场大纲里的每句话，主持人都要念出来。写完后逐句读一遍，问自己：一个有经验的主持人当面会不会这么说。

### 1. 常见 AI 腔和改法

| 不这样写 | 改成 |
| --- | --- |
| 能否请您分享一下……？ | 请您介绍一下……／请您帮我回忆一下……？ |
| 没有具体经历时问“您如何看待……？” | 先问经历：“您最近一次用它是什么情况？” |
| 整体而言，您的体验如何？ | 先问经历：“您最近一次用它是什么时候？当时用来做什么？”讲完再追问“用下来体验如何？” |
| 具体而言，…… | 删掉，直接问：“具体卡在哪一步？” |
| 是什么促使您决定……？ | 先还原经过：“您最早是什么时候开始想换的？当时发生了什么？”讲完再追问“当时是出于什么原因决定的？” |
| ……带来了怎样的价值？ | 用了之后，和之前相比有什么变化？ |
| 您的核心诉求是什么？痛点是什么？ | 当时最想解决的是哪件事？ |
| 对于您来说，…… | 删掉。 |
| 怎么弄的、弄过来、啥情况、拍板 | 怎么操作的、迁移过来、什么情况、最后决定 |
| 回头看、看一张图（模块名） | 换机成本回顾、概念测试 |
| 非常感谢您的分享！（每题之后都说） | 只在总结时说一次“感谢您的时间”。 |
| 那么，接下来我们进入第二部分。 | *接下来，我们聊聊换机之后的使用情况* |

### 2. 句子

- 主问题一般不超过 70 个字，追问不超过 40 个字。超出时先删修饰，再拆句。
- 删掉无信息的开头，例如“基于您刚才的回答”“围绕这个话题进一步展开”。
- 删掉连续的“您认为”“您觉得”，直接问对象和动作。
- 一个模块里交替使用“当时、怎么、哪些、为什么、有没有”，不要每句同一个开头。
- 不用三连并列“……、……以及……”，问题里不用破折号做解释。
- 研究目的、方法名称、证据类型和分析术语放在简报，不放进问题。
