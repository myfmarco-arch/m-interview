# 研究设计服务

## 研究性质

| 研究性质 | 可以获得 | 不能直接推出 |
|---|---|---|
| 探索 | 场景、语言、动机、替代和假设 | 总体比例和普遍程度 |
| 解释 | 行为如何发生、条件如何变化、为什么在意 | 统计因果和总体效应量 |
| 评估 | 具体体验、理解、顾虑、使用条件和改进方向 | 总体满意度、转化率和权重 |
| 预测 | 专家判断、可能机制、风险和前提 | 确定的未来事实 |

定量表达的 SRQ 标记为“仅生成假设”，不能把访谈结果写成总体结论。

## 形式匹配

三类形式各自能拿到什么，见 SKILL.md。座谈会不能替代多次个人深访；专家访谈不能替代用户体验观察。目标和形式不匹配时，先说明能获得和不能获得的证据，再缩小目标或更换形式。

## 方法选择

先确定证据，再按 [方法索引](../modules/methods/index.md) 选 1 个主方法。只有能增加证据且不挤占关键时间时才加入辅助方法。每个 SRQ 都要有证据类型、方法和结论边界。没有匹配的方法卡时标记为“本次适配方案”，不虚构方法名或出处，也不要堆叠方法名。

## SRQ 覆盖

每个 SRQ 至少对应一个核心主问题。每个核心主问题都能指回某个 SRQ；指不回的删掉或并入别的问题。对应关系写在简报的时间表里，现场大纲不标 SRQ。

结果要用来比较、排序或定优先级时，同一类证据要每个受访者都问到。做法是先让受访者自由讲，再用一条提示清单逐项补问没提到的类别。提示清单写成一行，不展开成多个问题。

## 样本

简报写一行样本：场次、分群，以及谁不在样本里。结果要支持决策时，检查幸存者偏差。例如只访“已经换机成功的人”，会漏掉中途放弃、退货或换回去的人，而他们往往遇到了最严重的问题。缺的人群不能补访时，在简报的证据边界里写明。

## 规则

| rule_id | 检查 | severity |
|---|---|---|
| `design.answerability` | 定量表达标记为仅生成假设 | warning |
| `design.format-fit` | 形式与目标匹配，不匹配时缩小目标或换形式 | error |
| `design.srq-evidence-method` | 每个 SRQ 有证据类型和主方法 | warning |
| `design.srq-coverage` | 每个 SRQ 至少有一个核心主问题；每个核心主问题能对应到某个 SRQ；简报时间表写明对应关系 | error |
| `design.comparable` | 需要跨受访者比较的 SRQ，在自由讲述后用同一条提示清单补问 | warning |
| `design.sample` | 简报写明场次、分群和样本外人群；支持决策时检查幸存者偏差 | warning |
| `design.disconfirm` | 重要假设有可能推翻它的问题 | info |
| `design.time-budget` | 时间包含开场、转场、刺激物、轮次和收尾，且不超过总时长 | error |
