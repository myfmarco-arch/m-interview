# 任务路由服务

工作模式和交付状态（blocked、draft、ready）见 SKILL.md。本文件定义澄清和伦理信息的唯一口径。

## 澄清规则

完整新建或修改前，必须确认访谈类型、预计时长、受访对象与资格、研究目标或业务应用。访谈类型可以是三类标准形式，也可以是自定义形式。首轮只追问这四项和会改变方法、伦理或现场流程的缺口。其他缺口进入 `draft`，不得写成事实。专家访谈还要确认用途（见专家形式模块）：能从请求里看出来就直接用，看不出来就在首轮问一次。

开场需要的研究用途、记录方式和匿名边界，来自用户在请求里的确认，或生效 overlay 的团队标准同意信息。两者都没有的项目，不阻断设计，按 SKILL.md 的 `draft` 交付。用户补齐后，删掉空位，状态改为 `ready`。

跳过和退出权利默认写明。发起方和后续安排未提供时，不点名发起方，不写具体安排；它们不阻断，也不留空位。外部专家看约访方式。通过双盲专家网络约访时，不介绍发起方；开场不逐项声明用途、记录、匿名、跳过和退出，这些按专家网络条款执行并写进简报，也不因此进入 `draft`。直接约访时按上面的常规处理。约访方式没说明时，按当前产品的默认；产品没有默认，就在首轮问一次。

自定义或混合形式必须声明继承的形式规则。没有声明时，只执行核心规则并停在 `draft`。

以下情况先交付或确认简报，再生成完整现场大纲：研究目标与形式不匹配；受访对象或资格未定；主方法尚未成立；刺激物或操作会改变问题顺序；伦理或保密边界可能改变回答。

快速提问只确认一个最影响问法的条件。条件仍不完整时，给出问题或设计草稿，不把假设写成受访者会听到的事实。

## 范围外

访谈转写、访谈分析、招募问卷和实时主持不进入本流程。说明边界，不伪装成大纲设计继续处理。

## 规则

| rule_id | 检查 | severity |
|---|---|---|
| `routing.out-of-scope` | 范围外请求说明边界，不继续伪装处理 | error |
| `routing.blocking-info` | 完整交付前已知类型、时长、对象、目标或决策 | error |
| `routing.clarify-scope` | 只追问会改变设计的缺口 | warning |
| `routing.quick-ask` | 快速提问最多确认一个条件，不强制两份文档 | warning |
| `routing.audit-findings-first` | 审核先列问题，用户要求时再重写 | warning |
| `routing.brief-first` | 目标、形式、对象、方法、刺激物或伦理边界未定时，先确认简报信息 | warning |
| `routing.delivery-state` | 明确当前是 blocked、draft 还是 ready；伦理信息未确认时只交付带空位的草稿，不称为可直接使用 | error |
