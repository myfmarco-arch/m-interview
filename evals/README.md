# 行为评测

评测分为四组：

- `conformance`：所有产品必须保留的研究判断、证据边界和伦理行为。
- `modules`：方法、知识和服务模块的输入、输出及边界。
- `product`：中文默认产品的格式、命名和交付偏好。
- `product-en`：英文最小产品，用于验证产品层可替换，不改变核心合同。

用例使用 `expected` 和 `forbidden` 描述行为，不要求固定文本。`targets` 引用规则 id；产品偏好用例可以不引用核心规则。评审提示词见 [judge-prompt.md](judge-prompt.md)，评分方式见 [scoring.md](scoring.md)。

## 质量评测

上面几组主要检查“守不守规矩”。大纲好不好，还要看问题本身。另有两类质量检查：

1. **植入缺陷召回**：`conformance/audit-planted-defects` 给一份植入 11 个已知缺陷的大纲（见 `fixtures/planted-defects-guide.md` 的注释），看审核能找出几个。先作为非阻断用例积累基线。
2. **盲评对照（人工）**：同一个需求，把 skill 产出和团队历史上公认的好大纲去掉标识后混在一起，由 2 位研究员按下表打分，再揭晓来源。

| 维度 | 看什么 |
|---|---|
| SRQ 覆盖 | 每个 SRQ 都有问题；没有对应不上的问题 |
| 可比性 | 需要比较的内容，每个受访者都会被问到 |
| 顺序 | 先宽后窄、先自发后提示、先经历后评价 |
| 问法 | 无预设、无将来意愿主问题、一题一事 |
| 口语 | 读出来像主持人说话，没有 AI 腔 |
| 现场可用 | 时间合理，分支清楚，大纲简洁 |

运行结果和盲评结果都不进版本库。`run_evals.py prepare` 默认写到 `evals/runs/`，该目录已被 `.gitignore` 忽略。需要长期保存时，用 `--out` 写到仓库目录外。盲评结果与模型评测分开存放。
