# 模块合同

`m-interview-contract-v1`。模块是可被产品选择、替换或通过 overlay 扩展的能力文件。

## 模块类型

| 类型 | 责任 | 例子 |
|---|---|---|
| `service` | 多种任务共用的能力 | 路由、研究设计、案头调研、验证 |
| `format` | 访谈形式的证据路径和现场节奏 | 用户深访、专家访谈、座谈会 |
| `method` | 具体访谈方法 | 关键事件、JTBD、非使用、案例法 |
| `knowledge` | 问法知识、知识边界和追问技巧 | 乔哈里视窗、证据边界 |
| `adapter` | 将研究产物转换为交付材料 | Markdown、专家外发版、访前告知 |
| `profile` | 产品工作流、写作、格式和命名默认值 | `interview-zh-default` |
| `overlay` | 替换或扩展产品配置 | 团队手卡格式、额外验证 |

## 方法模块章节

完整方法模块必须按顺序使用以下二级标题：

1. `## 解决的问题`
2. `## 适用条件`
3. `## 不适用条件`
4. `## 必需输入`
5. `## 证据链`
6. `## 产生的输出`
7. `## 可以得出`
8. `## 不能推出`
9. `## 验证规则`
10. `## 来源与许可`

## 现有方法卡

`references/modules/methods/` 中的现有方法卡还没有按以上十个章节改写，只能支持研究设计，不声明模块合同兼容性，也不能覆盖合同或官方验证规则。新增或正式升级的方法卡必须补齐十个章节，并增加对应的 modules 评测。

## 分层约束

- `knowledge` 和 `method` 不定义产品偏好，例如页数、标题或命名。
- `format` 定义形式的证据路径，不决定产品的具体排版。
- `adapter` 不改变 ResearchBrief、MethodPlan、SessionPlan 或 GuideSpec 的语义。
- `profile` 不改变合同和官方验证规则。
- overlay 不得覆盖合同、官方验证规则、研究事实或证据状态。
